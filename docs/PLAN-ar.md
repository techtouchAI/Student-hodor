# خطة عمل محكمة — إصلاح وإكمال Student Hodor

**التاريخ:** 2026-09-15 · **الفرع:** `arena/01a0a6f3-student-hodor`
**القاعدة:** كل بند هنا يُقابل بنداً في `ANALYSIS-ar.md` بنفس الرقم. لا ترقيع: كل إصلاح يعالج
الجذر (مصدر الحقيقة/النمط) لا العرض.

---

## مبادئ عامة تحكم كل تعديل

1. **مصدر حقيقة واحد:** التسلسل الفريد للطالب، مفاتيح الأشهر الميلادية، وتسميات/ألوان الحالات
   تعيش في `core/` و`data/` فقط؛ الشاشات تستهلكها.
2. **لا `FutureBuilder(future: ...)` داخل `build`:** إما `StreamBuilder` على `watch()`، أو مستقبل
   يُحفظ في `State` ويُعاد في `didUpdateWidget` عند تغيّر المدخلات فقط.
3. **لا استثناء صامت:** كل مسار `async` يلمسه المستخدم ملفوف بـ`try/catch` يعرض رسالة عربية عبر
   `SnackBar`، ويعيد الحالة (`_busy=false`) دائماً.
4. **تنقّل هرمي:** `push` للتفرعات (طلاب، باجات، مسح، تقرير طالب، كشف يوم) و`go` للجذور
   (رئيسة/إعدادات/سنوات) + `errorBuilder` عام.
5. **بوابة جودة:** `flutter analyze --fatal-infos` صفر ملاحظات + اختبارات وحدة لكل علة مُصلحة
   (تسلسل السنة، مفاتيح الأشهر، تعقيم أسماء الأوراق، ترحيل الإجازة إلى الحضور).
6. **هجرة لا إعادة إنشاء:** رفع `schemaVersion` إلى 2 مع `onUpgrade` يضيف الفهارس دون لمس البيانات.

## ترتيب التنفيذ والترحيل

1. دفعات كود مرتبة: `core` → `data` → `state` → `app` → الشاشات (واحدة واحدة) → `export` → اختبارات → docs.
2. دفعة واحدة إلى الفرع، ثم مراقبة `verify` في CI (analyze+test) وإصلاح ما يظهر، ثم مراقبة `apk`.
3. بعد الاخضرار: مراجعة تدقيق (`AUDIT-ar.md`) تقابل كل بند خطة بموضع كوده واختباره، ثم دفع نهائي.

## مخاطر معلومة وضوابطها

- **لا بيئة بناء محلية** (لا Flutter/pub في العزل): الضابط = CI + مراجعة ذاتية لكل ملف ضد قواعد
  `analysis_options` (const/trailing commas/mounted guards) قبل الدفع.
- **`flutter_localizations` يثبّت `intl`**: يُحذف قيد `intl` القديم بالكامل (غير مستخدم) فلا تعارض.
- **هجرة المخطط**: إضافة فهارس فقط (`CREATE INDEX IF NOT EXISTS`) — لا تغيير جداول، فلا فقد بيانات.
